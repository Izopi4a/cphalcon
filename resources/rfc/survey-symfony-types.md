# Survey: Symfony Form — type system, OptionsResolver, core types, CollectionType, ChoiceType
(Read-only survey by a research agent, 2026-10-15. Recent Symfony: has BaseType, PolymorphicCollectionType, entry_name, keep_as_list, Flow types.)

## 1. How a type is resolved
- Lookup: `FormRegistry::getType($fqcn)` asks each `FormExtensionInterface` (`hasType`/`getType`); else `new $name()` for any `FormTypeInterface` class.
- Resolving: `resolveType()` resolves `getParent()` recursively (circular-reference detection), collects `getTypeExtensions($fqcn)` from all extensions in registration order, then `ResolvedFormTypeFactory::createResolvedType($type, $exts, $parentResolved)` -> `ResolvedFormType`. Cached per name.
- Defaults: `AbstractType::getParent()` returns `FormType::class`. `FormType` and `ButtonType` return null; both extend `BaseType` (PHP superclass, not a parent type).
- Extensions: `AbstractExtension` indexes `loadTypes()` by class and `loadTypeExtensions()` by each entry of static `getExtendedTypes()`. `PreloadedExtension` takes ready arrays.
- Call order (same for `buildForm`, `buildView`, `finishView`): parent's resolved type (recursively), then inner type, then this type's extensions in order. For `TextareaType`: Form, Form's extensions, Text, Text's extensions, Textarea, Textarea's extensions. An extension on `FormType` runs for every type, before child types' own code.
- `getOptionsResolver()`: lazily `clone $parent->getOptionsResolver()`, then inner type's `configureOptions`, then each extension's. Children override parent defaults by calling `setDefaults` again.
- Lifecycle: `FormFactory::createNamedBuilder` -> `createBuilder` (resolve options, create `FormBuilder` with `data_class`) -> `$type->buildForm($builder, $builder->getOptions())`. `Form::createView` -> `$type->createView`, `buildView`, each child's `createView`, `finishView` (sees finished child views).

## 2. OptionsResolver: what FormType relies on
Public API: `setDefault(s)`, `hasDefault`, `setRequired`/`isRequired`/`isMissing`, `setDefined`/`isDefined`, `setOptions` (nested), `setDeprecated`, `setNormalizer`/`addNormalizer`, `setAllowedValues`/`addAllowedValues`, `setAllowedTypes`/`addAllowedTypes`, `define()` (`OptionConfigurator`), `setInfo`, `setPrototype`, `remove`, `clear`, `resolve`, `setIgnoreUndefined`, ArrayAccess on `Options`.
MUST KEEP: `setDefaults`; lazy defaults (a `\Closure` whose first param is typed `Options`, evaluated on demand: `data_class` from `data`, `empty_data` from `data_class`, `error_bubbling` from `compound`/`inherit_data`, ChoiceType `compound` = `expanded`); overriding lazy defaults (closure with 2nd `$previousValue` param chains, else replaces); `setNormalizer` (CollectionType forces `entry_options['block_name']='entry'`; ChoiceType `placeholder`); `setAllowedTypes` (incl. `'string[]'`, class names); `setAllowedValues` (DateType `widget`/`input`, IntegerType `rounding_mode`); `setDefined(['data'])` (optional, no default; FormType checks `array_key_exists('data')` to `setDataLocked`); `setRequired` (PolymorphicCollectionType); `clone` for parent->child inheritance; rejecting undefined options.
CAN DROP: `setOptions` nested, `setDeprecated`, `define()`/`OptionConfigurator`, `setInfo`, `setPrototype`, `addNormalizer` forcePrepend, `setIgnoreUndefined`, `remove`/`clear`. Previous-value chaining could be plain override.

## 3. Core types (parent / compound / what they add)
- `BaseType` (abstract): `disabled`, `auto_initialize`, `label`, `attr`, `row_attr`, `block_name`, `block_prefix`, `priority`, `translation_domain`, `form_attr`. View: `id`, `name`, `full_name` (`parent[name]`), `block_prefixes` (walks parent chain), `unique_block_prefix`.
- `FormType`: root, `compound`=true, sets `DataMapper`. See 6.
- `TextType`: `compound`=false; adds itself as view transformer (null -> '') when `empty_data===''`.
- Children of TextType: `EmailType`, `SearchType`, `TelType`, `RangeType` (block prefix only); `UrlType` (`FixUrlProtocolListener`); `ColorType` (`html5`); `PasswordType` (`always_empty`, `trim`=false, view `value`=''); `TextareaType` (newline-normalizing transformer).
- `HiddenType`: `required`=false, `error_bubbling`=true, `compound`=false.
- `CheckboxType`: `value`='1', `false_values`=[null], `BooleanToStringTransformer`, view `checked`; `is_empty_callback` is `false === data`. `RadioType`: parent CheckboxType.
- `ChoiceType`: see 5. Children (choice loaders): `EnumType`, `CountryType`, `LanguageType`, `LocaleType`, `CurrencyType`, `TimezoneType`.
- `CollectionType`, `PolymorphicCollectionType`: see 4.
- `RepeatedType`: `type`, `options`, `first_options`, `second_options`, `first_name`, `second_name`; two children + `ValueToDuplicatesTransformer`.
- `FileType`: `multiple`, `data_class`=`File` (lazy); PRE_SUBMIT listener filters uploads; `finishView` sets `multipart`=true (FormType::finishView bubbles up).
- `IntegerType`, `NumberType`, `MoneyType`, `PercentType`: localized-string view transformers, `scale`/`grouping`/`rounding_mode`; Number/Money add `StringToFloatTransformer` when `input`='string'.
- `DateType`, `TimeType`, `DateTimeType`, `DateIntervalType`, `WeekType`: `widget` ('single_text'|'choice'|'text'), `compound` = `widget !== 'single_text'`; compound adds year/month/day children (Choice or Integer) with array transformers, else string/HTML5 transformer; `input` ('datetime'|'datetime_immutable'|'string'|'timestamp'|'array'|'date_point') picks model transformers. `BirthdayType` parent DateType.
- `BoundsType` (min/max pair), `UuidType`, `UlidType`, `ButtonType`/`SubmitType`/`ResetType` (ButtonBuilder, not data forms).
- `TransformationFailureExtension`: the only core type extension; turns transformation failures into errors.

## 4. CollectionType (key feature)
Options: `entry_type` (TextType), `entry_options` (normalizer forces `block_name`='entry'), `allow_add`/`allow_delete` (false), `prototype` (true), `prototype_name` ('__name__'), `prototype_data`, `prototype_options`, `delete_empty` (bool|callable($childData)), `keep_as_list` (re-index 0..n), `entry_name` (name children after a property). Compound via FormType.
`buildForm`: if `allow_add && prototype`: `$builder->create(prototype_name, entry_type, required + label '__name__label__' + entry_options + prototype_options [+ data])->getForm()` stored via `setAttribute('prototype', ...)`. Always adds `ResizeFormListener($entry_type, $entry_options, allow_add, allow_delete, delete_empty, $prototypeOptions, keep_as_list, null, entry_name)`.
Views: `buildView` vars `allow_add`, `allow_delete`, `prototype` = `$prototype->setParent($form)->createView($view)`. `finishView` puts `'collection_entry'` into each entry's (and prototype's) `block_prefixes`, bubbles `multipart`.
`ResizeFormListener`: PRE_SET_DATA saves current children. POST_SET_DATA (prio 255): data must be array or Traversable&ArrayAccess; removes old children; for each `$key => $value` `$form->add($key, $type, $options + ['property_path' => "[$key]"])`. PRE_SUBMIT: non-array -> `[]`; if allowDelete remove children missing from submitted data; if allowAdd add a child per new key using prototype options (extra keys without allowAdd are ignored by mapper). SUBMIT (prio 50, before MergeCollectionListener): if deleteEmpty, for each valid synchronized empty child (new or allowDelete) unset data + remove child; if allowDelete unset data keys with no child (mapper only adds/overwrites, never removes); if keepAsList re-index data and children; finally `setData`.
Notes: entries get `property_path` `[key]`; `by_reference`=false makes parent's setter run; ChoiceType (multiple + by_reference) uses `MergeCollectionListener` (SUBMIT). `PolymorphicCollectionType` = same with `entry_types` (`string[]`), required `entry_type_provider` (`EntryTypeProviderInterface::forModelData/forSubmittedData`), `prototypes`.

## 5. ChoiceType (essentials)
`ChoiceListInterface`: `getChoices`, `getValues`, `getStructuredValues`, `getOriginalKeys`, `getChoicesForValues`, `getValuesForChoices`. Impl: `ArrayChoiceList`, `LazyChoiceList`. Built by `ChoiceListFactoryInterface::createListFromChoices`/`createListFromLoader` (`ChoiceLoaderInterface`) and `createView` -> `ChoiceListView` (`choices`, `preferredChoices`) of `ChoiceView` (`data`, `value`, `label`, `attr`) and `ChoiceGroupView`. Stored via `setAttribute('choice_list')`.
Matrix (expanded, multiple -> renders, compound, empty_data): (f,f) `<select>`, false, ''; (f,t) `<select multiple>` + `full_name.='[]'`, false, []; (t,f) radios, true, null; (t,t) checkboxes, true, []. Transformers: `ChoiceToValueTransformer` (single), `ChoicesToValuesTransformer` (multiple).
Expanded children: `buildForm` -> `addSubForms` over preferred + choices (flatten groups); each `ChoiceView` becomes a child named by index: `CheckboxType` (multiple, required=false) or `RadioType` with `value`, `label`, `attr`, `block_name`='entry'; optional `placeholder` child for radios; mapper `CheckboxListMapper` or `RadioListMapper`; PRE_SUBMIT listener converts submitted values into per-child values and collects unknown values (throw for single, FormError on POST_SUBMIT for multiple); `finishView` sets each child's `full_name` to parent name (+`[]` when multiple).
Other options: `choices`, `choice_loader`, `choice_label`, `choice_value`, `choice_name`, `choice_attr`, `group_by`, `preferred_choices`, `placeholder`. Defaults `trim`=false, `error_bubbling`=false.

## 6. FormType root options (BaseType + FormType)
`data` (setDefined only; locks data), `data_class` (lazy, class of `data`), `empty_data` (lazy: closure instantiating data_class or null if empty and not required; else `[]` if compound, else ''), `mapped` (true), `property_path` (null -> name), `getter`/`setter` (callables replacing property access), `inherit_data` (false), `compound` (true), `by_reference` (true; false => parent's setter always called with a copy), `error_bubbling` (lazy `compound && !inherit_data`), `trim` (true -> TrimListener PRE_SUBMIT), `required` (true), `disabled` (false), `label`, `label_attr`, `label_format`, `label_html`, `label_translation_parameters`, `attr`, `row_attr`, `help`, `help_attr`, `help_html`, `help_translation_parameters`, `method` ('POST'), `action` (''), `block_name`, `block_prefix`, `translation_domain`, `priority`, `auto_initialize`, `form_attr`, `allow_file_upload`, `allow_array_submission`, `post_max_size_message`, `upload_max_size_message`, `invalid_message`, `invalid_message_parameters`, `is_empty_callback`.
Added by type extensions on FormType (not core): `constraints`, `error_mapping`, `allow_extra_fields`, `extra_fields_message` (`Extension/Validator/Type/FormTypeValidatorExtension`); `validation_groups` (`BaseValidatorExtension`); `csrf_protection`, `csrf_field_name`, `csrf_token_id`, `csrf_token_manager`, `csrf_message` (`Extension/Csrf/Type/FormTypeCsrfExtension`). Mirroring this split keeps the core small.

Key files: `FormRegistry.php`, `ResolvedFormType.php`, `AbstractExtension.php`, `Extension/Core/Type/{BaseType,FormType,CollectionType,ChoiceType}.php`, `Extension/Core/EventListener/{ResizeFormListener,MergeCollectionListener}.php`, `Form.php` (createView ~L900), `FormFactory.php` (L85), `options-resolver/OptionsResolver.php` (lazy detection L185-243).
