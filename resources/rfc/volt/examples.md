# Volt NFR: examples, today vs proposed

Generated by `prototype/tools/examples.php`; every output below was produced by running the
template. "Today" is the stock extension built from upstream master (5.23.0). "Proposed" is the
patched parser (`prototype/patches/volt-parser.patch`) with the prototype engine
(`Phalcon\VoltNfr\Volt`). Regenerate with `./run.sh tools/examples.php --write`.

## E1. Nested blocks: a region opened by a middle layout (#17145)

The request from 2013: `leaf` extends `section` extends `base`, and the middle template opens regions that the leaf fills or extends with `super()`.

`base.volt`
```twig
<html><body>{% block body %}{% endblock %}</body></html>
```

`section.volt`
```twig
{% extends "base.volt" %}
{% block body %}
<main>{% block content %}{% endblock %}</main>
<aside>{% block sidebar %}<h3>Help</h3>{% endblock %}</aside>
{% endblock %}
```

`leaf.volt`
```twig
{% extends "section.volt" %}
{% block content %}Article{% endblock %}
{% block sidebar %}{{ super() }}<p>Related</p>{% endblock %}
```

**Today**
```text
render leaf → throws Phalcon\Mvc\View\Exception: Embedding blocks into other blocks is not supported in views/section.volt on line 3
```

**Proposed**
```text
render leaf → <html><body>
<main>Article</main>
<aside><h3>Help</h3><p>Related</p></aside>
</body></html>
```

## E2. A block inside if/for, and block() to print a block twice

`block_level` in base.c also counts if/for/switch, so today a block inside a condition fails with the nesting message. `block` is a keyword, so `block("title")` is a syntax error.

`layout.volt`
```twig
<title>{% block title %}Shop{% endblock %}</title>
<h1>{{ block("title") }}</h1>
{% if user %}{% block account %}Hi {{ user }}{% endblock %}{% endif %}
```

`orders.volt`
```twig
{% extends "layout.volt" %}
{% block title %}Orders{% endblock %}
{% block account %}{{ super() }} (3 open){% endblock %}
```

**Today**
```text
render orders, user=Ada → throws Phalcon\Mvc\View\Exception: Syntax error, unexpected token BLOCK in views/layout.volt on line 2
```

**Proposed**
```text
render orders, user=Ada → <title>Orders</title>
<h1>Orders</h1>
Hi Ada (3 open)
```

## E4. Components with embed

A card with overridable blocks, used twice with different content. Today this needs a macro per variation or a partial with HTML passed in as a string.

`card.volt`
```twig
<div class="card"><h2>{% block title %}{{ title }}{% endblock %}</h2>{% block body %}{% endblock %}</div>
```

`page.volt`
```twig
{% embed "card.volt" with ["title": "Orders"] %}
  {% block body %}<p>{{ open }} open</p>{% endblock %}
{% endembed %}
{% embed "card.volt" with ["title": "Stock"] %}
  {% block title %}{{ super() }} <small>low</small>{% endblock %}
  {% block body %}<p>2 items</p>{% endblock %}
{% endembed %}
```

**Today**
```text
render page → throws Phalcon\Mvc\View\Exception: Syntax error, unexpected token IDENTIFIER(embed) in views/page.volt on line 1
```

**Proposed**
```text
render page → <div class="card"><h2>Orders</h2><p>3 open</p></div><div class="card"><h2>Stock <small>low</small></h2><p>2 items</p></div>
```

## E5. Declaring a function: compile time today, run time proposed

Today a closure passed to `addFunction()` is a code generator: it runs once, at compile time, gets the arguments as PHP source, and must return PHP source. The value it computes is frozen into the cache. The proposal keeps that API for code generators and adds callables that run at render time.

Setup today:
```php
$compiler = $volt->getCompiler();
$compiler->addFunction('year', fn () => date('Y'));          // runs now, returns 2026
$compiler->addFunction('greeting', fn ($args) => 'Hello ' . $args); // returns 'Hello $name'
```

Setup proposed:
```php
$volt->addFunction(new VoltFunction('year', fn () => date('Y')));
$volt->addFunction(new VoltFunction('greeting', fn (string $name) => 'Hello ' . $name));
```

**Today**
```text
compile {{ year() }} → <?= 2026 ?>
compile {{ greeting(name) }} → <?= Hello $name ?>
```

**Proposed**
```text
compile {{ year() }} → <?= ($this->runtime['function:year'] ??= $this->getRuntimeFunction('year'))() ?>
compile {{ greeting(name) }} → <?= ($this->runtime['function:greeting'] ??= $this->getRuntimeFunction('greeting'))($name) ?>
```

## E6. Functions backed by a service, safe HTML, custom tests

An extension class lists functions and tests; `['prices', 'format']` is resolved from the DI container the first time a template calls it. `stars()` returns HTML and is declared safe, so autoescape leaves it alone. Today: no array callables, no safe flag, no test API (an unknown test compiles to `==`).

`product.volt`
```twig
{{ price(product.price) }} {{ stars(product.rating) }}
{% if user is premium %}Free shipping{% endif %}{% if user is not premium %}Shipping: {{ price(4.9) }}{% endif %}
```

Setup today:
```php
// no equivalent: addFunction('price', ['prices', 'format']) throws InvalidUserFunctionDefinition
```

Setup proposed:
```php
$di->setShared('prices', Prices::class);
$volt->addExtension(new ShopExtension());  // price, stars (safe), premium test
```

**Today**
```text
compile {% if user is premium %} → <?php if ($user == $premium) { ?>x<?php } ?>
```

**Proposed**
```text
render, premium user → 19.50 EUR <i class="star"></i><i class="star"></i>Free shipping
render, free user → 19.50 EUR <i class="star"></i><i class="star"></i>Shipping: 4.90 EUR
Prices instances → 1
compile {{ price(p) }} → <?= ($this->runtime['function:price'] ??= $this->getRuntimeFunction('price'))($p) ?>
typo: user is premiun → throws Phalcon\VoltNfr\Exception: Unknown test "premiun" in eval code on line 1
```

## E7. Escaping that is not applied twice

With autoescape on, today every echo is wrapped in `escaper->html()`, including escaping filters, and there is no `raw`.

**Today**
```text
compile {{ name|e }} → <?= $this->escaper->html($this->escaper->html($name)) ?>
compile {{ data|escape_js }} → <?= $this->escaper->html($this->escaper->js($data)) ?>
compile {{ html|raw }} → throws Phalcon\Mvc\View\Engine\Volt\Exceptions\UnknownVoltFilter: Unknown filter "raw" in eval code on line 1
```

**Proposed**
```text
compile {{ name|e }} → <?= $this->escaper->html($name) ?>
compile {{ data|escape_js }} → <?= $this->escaper->js($data) ?>
compile {{ html|raw }} → <?= $html ?>
```

## E8. Null coalescing and null-safe access

`|default` uses `empty()`, so `0` is replaced too; a missing relation fails with "Attempt to read property on null".

`invoice.volt`
```twig
{{ invoice.customer?.name ?? "(no customer)" }} | discount: {{ invoice.discount ?? "none" }} | {{ invoice.discount|default("none") }}
```

**Today**
```text
render, customer=null, discount=0 → throws Phalcon\Mvc\View\Exception: Syntax error, unexpected token DOT in views/invoice.volt on line 1
```

**Proposed**
```text
render, customer=null, discount=0 → (no customer) | discount: 0 | none
```

## E9. Editing a layout or a partial

Parents and static includes are inlined into the compiled child. Today only the child's own mtime is checked, so the edit is invisible until the cache is cleared; the prototype records what was inlined and checks it.

`layout.volt`
```twig
v1 {% block content %}{% endblock %}
```

`page.volt`
```twig
{% extends "layout.volt" %}{% block content %}page{% endblock %}
```

**Today**
```text
render page → v1 page
edit layout.volt (v2), render page → v1 page
```

**Proposed**
```text
render page → v1 page
edit layout.volt (v2), render page → v2 page
```

## E10. include ... with keeps the template's variables

Today adding `with` turns a compiled include into `$this->partial()`, which only sees the View's variables.

`row.volt`
```twig
<tr><td>{{ label }}</td><td>{{ currency }} {{ amount }}</td></tr>
```

`page.volt`
```twig
{% set currency = "EUR" %}
{% include "row" with ["label": "Total", "amount": 12] %}
```

**Today**
```text
render page → <tr><td>Total</td><td> 12</td></tr>
PHP warnings → Undefined variable $currency
```

**Proposed**
```text
render page → <tr><td>Total</td><td>EUR 12</td></tr>
```
