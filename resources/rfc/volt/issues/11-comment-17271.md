A possible shape for this, building on #NFR-07 (resolve inheritance on the AST).

Volt inlines the parent into the compiled child, so the parent has to be known when compiling. With a variable, it is only known at render time. The prototype keeps Volt's one-file model:
- a template whose `extends` is not a string literal compiles to a single call, `$this->renderDynamicExtends(<expr>, <child path>, get_defined_vars())`;
- at render time that call compiles the child against the parent it got, once per (child, parent) pair (`variant%%<hash>.php`), and runs it with the template's variables.

There is no block dispatch at run time, and the variants are recompiled when the child or the parent changes.

```twig
{# page.volt #}
{% extends request_is_ajax ? "ajax.volt" : "full.volt" %}
{% block content %}<p>{{ message }}</p>{% endblock %}
```

```
today:                  an empty page, with "Undefined index: value" and "file_get_contents(): … Is a directory"
proposed, ajax=false →  <html><p>Saved</p></html>
proposed, ajax=true  →  <p>Saved</p>
```

Example E3: https://github.com/Izopi4a/cphalcon/blob/nfr-volt/resources/rfc/volt/examples.md. Tests: `testExtendsFromAVariable`, `testExtendsFromAConditionalExpression` in https://github.com/Izopi4a/cphalcon/blob/nfr-volt/resources/rfc/volt/prototype/tests/Prototype/InheritanceTest.php

There are two limits in the prototype. Only the rendered template may use a variable (a middle layout with a dynamic parent is an error), and the value must be a template name, not an array of fallbacks.

The other option is Twig-style runtime dispatch, where each template is compiled to a class and blocks are called at render time. That handles every case, but it changes Volt's output model. Which direction would you prefer?
